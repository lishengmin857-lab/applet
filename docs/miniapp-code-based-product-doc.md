# 文案润色小程序说明文档（基于当前代码）

## 2. 项目概述

这是一个“AI 文案润色”微信小程序，用户输入原始文案后，可选择不同润色风格和目标字数，通过后端接口生成润色结果，并可复制、查看历史记录、切换 VIP 状态。

当前代码中的产品定位更接近：

- 输入原始文案
- 选择润色风格
- 选择生成字数
- 调用接口生成结果
- 本地保存生成记录
- 在记录页查看、复制、删除历史
- 在个人页查看额度并切换 VIP 状态

## 3. 页面结构

`app.json` 中当前共配置 3 个页面：

1. `pages/index/index`
2. `pages/records/records`
3. `pages/profile/profile`

当前通过底部导航模板在这 3 个页面之间跳转，跳转方式使用 `wx.redirectTo`。

## 4. 全局配置与初始化

### 4.1 全局接口地址

在 `app.js` 中，当前接口基础地址为：

`https://xiezuozhushou.site`

首页生成接口会请求：

`POST /api/v1/miniapp/copy/generate`

### 4.2 本地存储初始化

应用启动时会执行 `initStorage()`，完成以下初始化：

- 按天重置免费额度
- 初始化 `records`
- 初始化 `favorites`
- 初始化 `totalGenerateCount`
- 初始化 `isVip`

### 4.3 免费额度规则

当前代码实现的规则如下：

- 每日免费生成次数默认为 10 次
- 通过 `lastUseDate` 判断是否跨天
- 跨天后重置 `dailyRemainCount = 10`
- VIP 用户不受免费次数限制

## 5. 首页功能说明

首页是核心功能页，负责输入、参数选择和生成结果展示。

### 5.1 输入区

用户可在文本框中输入或粘贴待润色文案。

当前规则：

- 最大输入长度：1000 字
- 输入为空时不可正常生成
- 输入少于 3 个字符时提示内容过短
- 页面会实时显示当前字数

### 5.2 粘贴功能

点击“粘贴文本”后，页面会优先读取系统剪贴板。

处理逻辑：

- 若剪贴板有内容，则直接填入输入框
- 若读取失败或内容为空，则使用一段内置示例文案进行模拟填充

这意味着当前产品支持“快速试用”，即便用户没有提前复制文本，也能直接体验生成流程。

### 5.3 风格选择

当前代码中已实现 6 种风格：

1. `funny`：幽默
2. `sincere`：真诚
3. `professional`：专业
4. `poetry`：诗词
5. `aesthetic`：唯美
6. `romantic`：浪漫

默认选中风格：

`sincere`

页面会同时维护：

- 风格 key：用于接口请求
- 风格中文名：用于结果弹窗展示

### 5.4 字数选择

当前可选字数上限为：

- 50
- 100
- 200
- 300

默认值为：

`50`

该值会作为 `maxChars` 随生成请求一起传给后端。

### 5.5 生成校验

点击“开始润色”时，首页会按以下顺序校验：

1. 输入内容不能为空
2. 输入内容长度不能小于 3
3. 非 VIP 用户必须还有剩余额度

若免费额度已用完，会弹出提示框，提示今日免费次数已用完。

### 5.6 生成请求

首页会向后端发送如下字段：

```json
{
  "inputText": "用户输入的原始文案",
  "style": "sincere",
  "maxChars": 100
}
```

请求特征如下：

- 请求方法：`POST`
- 请求头：`Content-Type: application/json`
- 超时时间：`60000ms`

成功条件：

- HTTP 状态码为 2xx
- 返回结果中包含 `resultText`

### 5.7 生成成功后的处理

生成成功后，前端会构造一条记录并保存到本地：

```json
{
  "id": "记录ID",
  "inputText": "原始文案",
  "resultText": "润色结果",
  "style": "sincere",
  "isFavorite": false,
  "createdAt": 1710000000000
}
```

随后会执行：

- 写入 `records`
- 非 VIP 用户扣减 1 次当日额度
- `totalGenerateCount + 1`
- 打开结果弹窗展示生成内容

### 5.8 结果弹窗功能

生成完成后，首页会弹出结果窗口。

当前弹窗支持：

- 展示润色结果
- 展示当前风格名称
- 一键复制结果
- 重新生成
- 关闭弹窗

代码中还实现了“收藏切换”的逻辑方法 `onToggleFavorite`，但当前首页弹窗的 WXML 没有实际放出收藏按钮，因此该能力目前属于“代码已写、界面未开放”状态。

### 5.9 分享能力

首页在 `onLoad` 时会尝试开启分享菜单，支持：

- 分享给好友
- 分享到朋友圈

并定义了：

- `onShareAppMessage`
- `onShareTimeline`

## 6. 记录页功能说明

记录页用于展示历史生成记录。

### 6.1 数据来源

记录页数据来自本地存储中的：

`records`

### 6.2 列表规则

记录页会在 `onShow` 时重新加载数据，并执行：

- 按 `createdAt` 倒序排列
- 将时间格式化为 `YYYY-MM-DD HH:mm`

### 6.3 展示内容

每条记录当前展示：

- 风格标签
- 生成时间
- 原始文案
- 润色结果

### 6.4 支持操作

记录页当前支持两项操作：

1. 复制结果
2. 删除记录

删除时会先弹出确认框，确认后才真正从本地存储中移除。

### 6.5 空状态

若当前没有任何生成记录，页面会显示空状态，并提供“开始润色”按钮，点击后跳转回首页。

## 7. 个人页功能说明

个人页主要展示用户状态和一些轻量操作入口。

### 7.1 用户状态展示

个人页当前展示：

- 是否为 VIP
- 今日剩余额度
- 累计润色次数

其中：

- VIP 用户显示无限额度
- 非 VIP 用户显示 `dailyRemainCount`

### 7.2 VIP 切换

当前代码中的 VIP 是本地模拟切换，不涉及真实支付。

点击相关入口后会：

- 将 `isVip` 在 `true/false` 之间切换
- 更新本地存储
- Toast 提示当前状态变化

因此当前更像测试开关或体验模式，不是正式会员系统。

### 7.3 其他入口

个人页还提供：

- 分享给好友
- 使用指南
- 联系客服

其中“联系客服”通过微信按钮 `open-type="contact"` 打开。

## 8. 本地存储字段说明

当前代码中使用到的本地存储字段如下：

### 8.1 `records`

类型：数组

作用：保存历史生成记录

### 8.2 `favorites`

类型：数组

作用：预留收藏能力

说明：当前代码虽然初始化了这个字段，但记录页和个人页都没有正式使用该列表。

### 8.3 `dailyRemainCount`

类型：数字

作用：保存当日剩余免费次数

### 8.4 `lastUseDate`

类型：字符串

作用：用于判断是否跨天，从而决定是否重置额度

### 8.5 `totalGenerateCount`

类型：数字

作用：记录累计生成次数

### 8.6 `isVip`

类型：布尔值

作用：标识用户当前是否为 VIP

## 9. 接口说明

根据当前代码，首页只明确依赖 1 个后端接口。

### 9.1 生成文案接口

请求地址：

`POST https://xiezuozhushou.site/api/v1/miniapp/copy/generate`

请求参数：

```json
{
  "inputText": "string",
  "style": "funny | sincere | professional | poetry | aesthetic | romantic",
  "maxChars": "50 | 100 | 200 | 300"
}
```

前端期待的成功返回至少包含：

```json
{
  "id": "string",
  "resultText": "string"
}
```

前端还允许 `id` 缺省。若后端未返回 `id`，前端会使用当前时间戳作为记录 ID。

## 10. 当前实现特点与限制

### 10.1 已实现的核心闭环

当前代码已经跑通以下主流程：

1. 输入文案
2. 选择风格
3. 选择字数
4. 调用接口生成
5. 查看结果
6. 复制结果
7. 本地保存历史
8. 在记录页查看和删除

### 10.2 当前未完全落地的部分

以下能力在代码里有痕迹，但未完整形成最终功能：

- `favorites` 已初始化，但没有独立收藏页
- `onToggleFavorite` 已有逻辑，但首页结果弹窗没有收藏按钮
- 旧策划文档中提到的更多页面和模块，当前代码并未全部实现

### 10.3 当前实现方式偏本地化

除生成接口外，以下数据都以本地存储为主：

- 生成记录
- 免费额度
- VIP 状态
- 累计生成次数

这意味着当前版本更像一个前端 MVP 或演示版本，而不是完整的线上账号体系版本。
